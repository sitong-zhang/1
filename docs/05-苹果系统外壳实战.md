# 05 · 苹果系统外壳实战

> 前三章讲的是「一块玻璃怎么做」。
> **这一章讲的是：把几十块玻璃拼成一个"看起来像 iOS"的系统外壳，会遇到哪些只有做外壳才会遇到的问题。**
>
> 这一章里的结论，绝大部分不是"设计出来的"，而是"被坑出来的"：
> 锁屏能看到主屏、打开 App 时玻璃里是上一帧、底部上滑手势抢了别的控件……
> 每一个都对应代码里一处**看起来很不起眼、但删掉就出问题**的写法。
>
> 对应源码目录：[`../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/`](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/)

## 1. 这一阶段做了什么，没做什么

用户给的边界是"**先只做系统外壳**"。所以先把"外壳"定义清楚：

| 属于外壳（已做） | 不属于外壳（故意留空） |
|---|---|
| 锁屏（时间、通知、上滑解锁） | 真实 App 的业务逻辑 |
| 主屏（图标网格、分页、Dock、抖动编辑） | 真实 App 的真实内容 |
| 状态栏（时钟 / 信号 / Wi-Fi / 电池） | 真实信号与电量的读取 |
| 灵动岛（收起 / 展开） | 真实媒体会话 |
| 控制中心（下拉、面板、锁定、换壁纸） | 亮度/音量真实系统开关 |
| 通知中心（下拉、通知卡） | 真实通知监听 |
| 多任务（卡片、上滑移除） | 真实进程截图 |
| App 打开 / 关闭的缩放转场 | 真实 Activity 跳转 |

**这个边界很重要**：它决定了每个 App 打开后是[占位页](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosAppWindow.kt#L205-L271)，
而不是 36 个假 App。**"外壳是真的，App 是空的"**，比"每个 App 都假得像真的"更诚实，也更好交接。

## 2. 分层：整个外壳的 z-order（**本章最重要的一节**）

### 2.1 真实设备的 z-order，照搬到 Compose

[iOS 外壳](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt)的组合顺序 = **屏幕从下往上的物理堆叠顺序**。
在 Compose 里没有真正的 z-index，**书写顺序就是 z 序**。所以这一段的顺序一旦写错，
玻璃就会采到空纹理、或者采到上一帧。

```
┌─────────────────────────────────────────────────────────────┐
│  IosDynamicIsland      灵动岛（硬件挖孔，永远最上，纯黑）      │  ← 最后画
├─────────────────────────────────────────────────────────────┤
│  IosHomeGesture        底部上滑条 + Home Indicator            │
│  IosPullDownZones      顶部左右两条隐形下拉区                  │
├─────────────────────────────────────────────────────────────┤
│  IosNotificationCenter 通知中心   ← 采 overlayBackdrop         │
│  IosControlCenter      控制中心   ← 采 overlayBackdrop         │
│  IosAppSwitcher        多任务（纯遮罩，无玻璃）                │
│  IosLockScreen         锁屏       ← 采 overlayBackdrop         │
├─────────────────────────────────────────────────────────────┤
│  IosStatusBar          状态栏（**故意不录进内容层**）           │
├─────────────────────────────────────────────────────────────┤
│  ┌── Box + layerBackdrop(surfaceBackdrop)（条件挂载）──────┐  │
│  │  IosOpenAppWindow   打开 App：App 内玻璃采 appBackdrop   │  │
│  │  IosHomeScreen      主屏：Dock 玻璃采 wallpaperBackdrop  │  │
│  └────────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│  IosWallpaper          程序化壁纸 ─layerBackdrop→ wallpaper   │  ← 最先画
└─────────────────────────────────────────────────────────────┘
```

对应代码：[IosShell.kt L82-L151](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt#L82-L151)。

### 2.2 三条只有做外壳才会懂的排布规则

**规则 A：状态栏必须在内容层之上、但不在被录的那一层里。**

注释原文写得很清楚：

```kotlin
// ---- surfaces above the content -----------------------------------------------------
// The status bar sits above the content layer so it stays readable over an open app, whose
// window is opaque. It is not part of the recorded layer, which also means it survives the
// pull-down panels drawn later.
IosStatusBar(isLightTheme = isLightTheme, modifier = Modifier.align(Alignment.TopCenter))
```

为什么不录进去：控制中心/通知中心被拉下来时，它们自己的大字号时间会顶上来，
**如果状态栏被录进 `surfaceBackdrop`，它就会以"被模糊的背景的一部分"再次出现在玻璃里**，
结果是屏幕上出现两个时间。真实 iOS 里状态栏是被面板盖住的 —— 所以它必须**在内容层之外**。

**规则 B：灵动岛永远最后画，而且永远不是玻璃。**

[IosSystemChrome.kt L170-L239](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosSystemChrome.kt#L170-L239) 里它是一块
`Color.Black` + `RoundedCornerShape` 的实心胶囊，**没有 `drawBackdrop`**。

原因：灵动岛是**硬件挖孔（cut-out）**，不是玻璃。它的黑是"屏幕没这儿"，不是"玻璃很暗"。
把它玻璃化会立刻变成"假的"——因为玻璃会透出背景，而挖孔不会。

> **这条原则可以推广**：外壳里凡是"物理上不存在"的东西（挖孔、Home 条的黑白），都不要套材质。

**规则 C：手势层只在"该响应手势的状态"才挂载。**

```kotlin
if (!state.isLocked && !state.appSwitcher) {
    IosPullDownZones(state)
    IosHomeGesture(state = state, isLightTheme = isLightTheme)
}
```

[IosShell.kt L138-L141](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt#L138-L141)

- 锁屏时不能下拉控制中心（真实 iOS 锁屏下拉是通知中心，由锁屏自己的手势处理）；
- 多任务界面里上滑是"关闭多任务"，不是"回主屏"。

**条件挂载手势层，比在回调里写 if 更干净**：没挂载 = 不可能误触发，也不会抢走别处的拖动。

### 2.3 backdrop 分配表（背下来）

| 谁 | 采哪块 backdrop | 为什么 |
|---|---|---|
| 主屏 Dock 卡片 | `wallpaperBackdrop` | Dock 直接压在壁纸上 |
| App 窗口内的玻璃 | `appBackdrop`（窗口自己新建） | 窗口是不透明底，玻璃只能折射窗口内部 |
| 锁屏上的玻璃 | `overlayBackdrop` = 组合(壁纸, 内容层) | 锁屏压在"壁纸 + 主屏"之上 |
| 控制中心 / 通知中心 | `overlayBackdrop` | 同上：必须能糊掉主屏图标（这正是苹果的做法） |
| 多任务 | 不用 backdrop | 它是一层纯黑 42% 遮罩 + 程序化卡片，没有玻璃 |
| 灵动岛 / 状态栏 / Home 条 | 不用 backdrop | 不是玻璃 |

## 3. backdrop 的建立与"条件录制"

### 3.1 `IosScaffold`：两块画布，18 行

[IosScaffold.kt L130-L148](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosScaffold.kt#L130-L148)：

```kotlin
Box(Modifier.fillMaxSize()) {
    val wallpaperBackdrop = rememberLayerBackdrop()   // 层 0：壁纸
    val surfaceBackdrop = rememberLayerBackdrop()     // 层 1：屏幕内容（由 shell 条件挂载）

    IosWallpaper(
        isLightTheme = isLightTheme,
        variant = wallpaperVariant,
        modifier = Modifier.fillMaxSize().layerBackdrop(wallpaperBackdrop)
    )
    content(wallpaperBackdrop, surfaceBackdrop)
}
```

它把"壁纸"和"屏幕内容"**分成两块画布**，是因为它们被采样的人生阶段不同：

- 主屏自己内部的玻璃（Dock）**只要有壁纸就够了** → 采 `wallpaperBackdrop`；
- 浮层（锁屏/控制中心）**要同时看到壁纸和主屏图标** → 采两者的组合。

如果只有一块画布（上游 Demo 的做法），主屏内部玻璃和浮层玻璃就都采同一张，
"浮层要把主屏图标糊掉"这件事就做不到。

### 3.2 条件录制：外壳唯一的性能开关

[IosShell.kt L77-L99](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt#L77-L99)：

```kotlin
// Recording the content layer costs a full-screen offscreen pass every frame, so it only
// runs while something above actually reads it.
val surfaceIsRead = state.isLocked || state.controlCenter || state.notificationCenter

Box(
    Modifier
        .fillMaxSize()
        .then(if (surfaceIsRead) Modifier.layerBackdrop(surfaceBackdrop) else Modifier)
) {
    IosHomeScreen(backdrop = wallpaperBackdrop, state = state, isLightTheme = isLightTheme)
    IosOpenAppWindow(state = state, backdrop = wallpaperBackdrop, isLightTheme = isLightTheme)
}
```

**`surfaceIsRead` 的三个条件，正好对应三个"有东西在采它"的状态**：

| 状态 | 谁在读 `surfaceBackdrop` |
|---|---|
| `isLocked` | 锁屏的玻璃（通知卡、手电/相机按钮） |
| `controlCenter` | 控制中心面板里的所有玻璃方块 |
| `notificationCenter` | 通知中心的玻璃卡 |

**为什么值钱**：录一帧 = 一次全屏离屏渲染。用户在主屏左右翻页、点图标、看动画时，
**没有任何东西在读这一层**，如果不做条件录制，这些操作全程都在白烧一次全屏 offscreen pass。
上游 Demo 页面少、内容简单可以无脑常开；**做系统外壳必须条件录制**。

> ⚠️ 常见的翻车点：把 `surfaceIsRead` 的条件写漏一项（比如忘了 `notificationCenter`），
> 表现是"能打开通知中心，但玻璃里是空的 / 是上一帧"。**改这个条件时，要同时想到 3 个上层消费者。**

## 4. 状态机：`IosShellState`

[IosShellState.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShellState.kt)。

**为什么不用 Navigation 库**：这不是"页面跳转"，而是**一个连续系统里的并发状态**
（锁屏开着的同时可能有 App 在后台、控制中心可以盖在锁屏上、多任务可以盖在主屏上）。
Navigation 的 destination 栈模型表达不了这种"多个层同时存在"，硬套只会把简单问题搞复杂。

**为什么用单一 holder 而不是十几个 `remember { mutableStateOf }`**：
`IosHomeScreen`、`IosShell`、`IosLockScreen`、`IosOverlays` 都要读写同一批状态，
用一个 `@Stable` class 传下去，比串十几组 `value/onValueChange` 干净得多，也不会出现"两个地方各存一份 page"的同步 bug。

### 4.1 字段表

| 字段 | 类型 | 含义 |
|---|---|---|
| `surface` | `IosSurface`（`Lock` / `Home`） | 当前是锁屏还是主屏 |
| `page` | `Int` | 主屏当前页（由 `Pager` 的 `snapshotFlow` 回写） |
| `openApp` | `IosApp?` | 当前全屏占据的 App |
| `openAppOrigin` | `Rect` | **启动它的那个图标在主屏上的矩形** → 转场的起点 |
| `recents` | `SnapshotStateList<IosApp>` | MRU，最新在前，上限 6 |
| `controlCenter` / `notificationCenter` / `appSwitcher` | `Boolean` | 三个浮层 |
| `jiggle` | `Boolean` | 主屏抖动编辑模式 |
| `islandExpanded` | `Boolean` | 灵动岛是否展开 |
| `wallpaper` | `Int` | 壁纸变体（控制中心里 `++` 循环） |
| `galleryOpen` | `Boolean` | 当前 App 是否是那个"组件画廊" |

### 4.2 `homeGesture()`：一个手势，三种含义

[IosShellState.kt L118-L127](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShellState.kt#L118-L127)：

```kotlin
fun homeGesture() {
    when {
        appSwitcher -> appSwitcher = false          // 在多任务里 → 回主屏
        openApp != null -> goHome()                 // 在 App 里   → 回主屏
        else -> { jiggle = false; appSwitcher = true }  // 在主屏   → 打开多任务
    }
}
```

**这就是为什么它必须写在 state 里、而不是写在手势回调里**：
"从底部上滑"这个手势的语义**取决于当前状态**，而当前状态只有 state 知道。
写在回调里就得把 `appSwitcher`、`openApp`、`jiggle` 三个值再传一遍。

### 4.3 `lock()` 必须"清场"

```kotlin
fun lock() {
    jiggle = false
    closeApp()
    closeOverlays()
    islandExpanded = false
    surface = IosSurface.Lock
}
```

锁屏是**最底层的状态**，任何上层浮层都不该跨过这次锁定存活。
漏一行的表现是："锁定后再解锁，控制中心还开着 / 灵动岛还张着嘴"。

## 5. 锁屏

[IosLockScreen.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosLockScreen.kt)

### 5.1 结构（从上到下）

```
Spacer(84dp)
锁形玻璃按钮（GlassIconButton, 42dp）
"10 月 1 日 星期四"（白 90%, 17sp Medium）
大时间 88sp Light（rememberIosClock，每秒刷新）
Spacer(28dp)
通知卡 ×2（GlassCard, corner 26dp, surfaceColor = White 14%）
Spacer(weight 1f)      ← 把下面对齐到底部
手电筒 / 相机  玻璃按钮 ×2（52dp，左右各一，padding 44dp）
"上滑解锁"（白 75%, 14sp）
Spacer(30dp)
```

**文字恒白、与主题无关**：锁屏永远直接压在原始壁纸上，真实 iOS 的锁屏也是恒白。
所以这里**不要**用 `IosColors.content(isLightTheme)`。

**通知卡的 `surfaceColor` 是 14% 而不是通知中心的 22%**：锁屏的卡直接坐在鲜艳的原图上，
染色再高就会盖掉壁纸。这是 04 章"克制阶梯"在锁屏上的具体取值。

### 5.2 上滑解锁的三个数字

```kotlin
val offsetY = remember { Animatable(0f) }

.draggable(
    orientation = Orientation.Vertical,
    state = rememberDraggableState { delta ->
        scope.launch { offsetY.snapTo((offsetY.value + delta).coerceIn(-2_400f, 0f)) }
    },
    onDragStopped = { velocity ->
        if (offsetY.value < -180f || velocity < -1_100f) {
            offsetY.animateTo(-2_400f, tween(300, easing = EaseOutCubic))
            onUnlock()
        } else {
            offsetY.animateTo(0f, spring(Spring.DampingRatioMediumBouncy, Spring.StiffnessMediumLow))
        }
    }
)
```

| 数字 | 含义 | 为什么是它 |
|---|---|---|
| `-180f` | 位移阈值（px） | 太小 → 轻微误触就解锁；太大 → 感觉"推不动" |
| `-1_100f` | 速度阈值（px/s） | 快甩即使位移不够也解锁 —— 这是"手感"的关键 |
| `-2_400f` | 解锁时的目标位移 | 足够远，保证整屏移出屏幕（不需要精确等于屏高） |
| `tween(300, EaseOutCubic)` | 解锁动画 | 先快后慢，符合"甩出去"的物理 |
| `spring(MediumBouncy, MediumLow)` | 回弹 | 松手没够阈值 → 弹回去，带一点过冲 |

**注意 `coerceIn(-2400f, 0f)`：只允许往上滑。** 不加这句，锁屏可以被往下拖出一个空白缺口。

### 5.3 ⚠️ 一行必须存在的代码：吞掉点击

```kotlin
// Swallow stray taps so they cannot reach the home screen behind the lock screen.
.clickable(interactionSource = null, indication = null) {},
```

**这行看起来毫无作用（空 lambda），但它是必需的。** 原因：

在 `IosShell` 里，锁屏和主屏是**同一个 `Box` 里同时组合的两个兄弟节点**。
主屏的图标在锁屏下面**依然存在、依然可点**。
`draggable` 只吃"拖动"手势，**不阻止 clicks** —— 所以如果锁屏上不加这个空的 `clickable`，
用户在锁屏上随手一点，点到的地方如果正好是主屏某个图标，那个 App 就会在锁屏后面被打开。

> **通用规律：任何"盖在可交互内容之上的全屏层"，都必须显式吞掉它不处理的手势。**
> `interactionSource = null, indication = null` 是为了不显示水波纹 —— 这是上游 Ripple 之外更轻的一档。

### 5.4 已知问题：锁屏与主屏的关系（见 §14.2）

当前实现里锁屏是**与主屏并列的一个兄弟节点**，靠"整体上移 + 主屏被完全盖住"来表现解锁。
这在视觉上已经可用，但和真实 iOS 有差别，**这是本阶段最值得接手继续改的一处**，详见 §14.2。

## 6. 主屏

[IosHomeScreen.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosHomeScreen.kt)

### 6.1 为什么**手写**网格，而不是 `LazyVerticalGrid`

代码注释原话：

> Icons are laid out by hand rather than with a lazy grid so the four columns keep identical
> widths on every page (and on the short last row), which is what makes the dock and the dots
> line up with the grid above them.

关键在"**最后一行的短行**"：第 2 页只有 16 个图标（4×4），如果用一个自动流转的 lazy grid，
列宽会因为内容数量而漂移，**Dock 与上面的图标就不会左右对齐**。

写法是 `apps.chunked(4)` + 每列 `Modifier.weight(1f)` + 不足 4 个时补 `Spacer(Modifier.weight(1f))`：

```kotlin
rowApps.forEachIndexed { columnIndex, app ->
    Box(Modifier.weight(1f), contentAlignment = Alignment.TopCenter) { IosHomeIcon(...) }
}
repeat(4 - rowApps.size) { Spacer(Modifier.weight(1f)) }
```

### 6.2 图标尺寸与"苹果味"的 5 个参数

| 参数 | 值 | 说明 |
|---|---|---|
| 图标边长 | `62.dp` | |
| 圆角 | `RoundedRectangle(15.dp)` | **≈ 边长的 24%**，且必须用 `com.kyant.shapes` 的 G2 连续曲率 |
| 底色 | `Brush.linearGradient(app.top, app.bottom)` | 每个 App 一组双色渐变（见 06 章） |
| 内容 | `GlassIcon(app.glyph, app.glyphTint, size = 31dp)` | 白色（或深色）单色矢量 |
| 阴影 | `shadow(10.dp, RoundedRectangle(15.dp), ambient/spot = Black 40%)` | 让图标"浮"在壁纸上 |
| 标签 | `12.sp` `Medium` 白色 + `Shadow(Black 45%, offset(0,1), blur 3)` | 亮壁纸上也读得清 |

`RoundedRectangle(15.dp)` 在这份代码里出现了 **3 次**（图标、阴影、裁剪），必须一致，
否则阴影边缘会和图标边缘错开半个像素，出现一圈"鬼影"。

### 6.3 抖动编辑模式（jiggle）

```kotlin
val wobble = if (jiggle) {
    val transition = rememberInfiniteTransition(label = "jiggle")
    val angle by transition.animateFloat(
        initialValue = -1.1f,
        targetValue = 1.1f,
        animationSpec = infiniteRepeatable(
            animation = tween(130 + phase * 26, easing = LinearEasing),
            repeatMode = RepeatMode.Reverse
        )
    )
    angle
} else 0f

Column(Modifier.graphicsLayer { rotationZ = wobble })
```

三个细节，缺一个就不像：

1. **`phase = (rowIndex * 4 + columnIndex) % 4`** → 周期从 130ms 到 208ms 错开，
   **图标不同步才是苹果的样子**；所有图标同频抖动会像"整屏在呼吸"。
2. **±1.1°** —— 超过 2° 就变成"摇酒器"了。
3. **`rotationZ` 而不是 `offset`** —— 苹果是绕中心旋转，不是平移。

编辑态的退出也照抄 iOS：点空白处退出（`IosHomeScreen` 顶部那个 `if (state.jiggle)` 的全屏 `clickable`），
以及在编辑态禁用翻页（`userScrollEnabled = !state.jiggle`）。

### 6.4 分页与圆点

```kotlin
val pagerState = rememberPagerState(pageCount = { IosAppCatalog.pages.size })

LaunchedEffect(pagerState) {
    snapshotFlow { pagerState.currentPage }.collectLatest { state.page = it }
}
```

**方向是"Pager → state"，不是"state → Pager"**：Pager 是手势的真相来源，
把它单向同步到 state，供 Dock / 圆点读取。反过来写会出现"手势滚到一半，state 先跳"的抖动。

圆点 7dp、`Capsule()`、当前页白 95% / 其余白 38%。

## 7. 打开 / 关闭 App 的缩放转场

[IosAppWindow.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosAppWindow.kt)

这是整个外壳里**最难写对**的一段动画。

### 7.1 需求：从图标"长"成整屏，而且文字不能重排

天真的写法是"给全屏内容加 `scaleX/scaleY`"，但那样**文字会随缩放一起被拉伸**，
过渡中文字是糊的、变形的。

**正确做法：位置和尺寸都插值，内容只布局一次。**

```kotlin
val left = lerp(origin.left, screen.left, fraction)
val top = lerp(origin.top, screen.top, fraction)
val width = lerp(origin.width, screen.width, fraction)
val height = lerp(origin.height, screen.height, fraction)
val corner = lerp(with(density) { IconCornerDp.dp.toPx() }, 0f, fraction)

Box(
    Modifier
        .offset { IntOffset(left.roundToInt(), top.roundToInt()) }
        .size(width.toDp(), height.toDp())
        .clip(RoundedRectangle(corner.toDp()))
) {
    Box(
        Modifier
            .requiredSize(screen.width.toDp(), screen.height.toDp())   // ← 永远按真实屏幕尺寸布局
            .graphicsLayer {
                transformOrigin = TransformOrigin(0f, 0f)              // ← 左上角为锚点
                scaleX = width / screen.width
                scaleY = height / screen.height
            }
    ) {
        IosAppSurface(...)
    }
}
```

两个关键点：

1. **`requiredSize(整屏)` + `graphicsLayer` 缩放**：内容按真实尺寸布局（文字换行、字号都是最终值），
   再整体被压进那个正在变大的盒子里。**整个过渡中内容都是"最终形态的一个缩放"，永远不会重排。**
2. **`transformOrigin = TransformOrigin(0f, 0f)`**：默认锚点是中心，中心缩放会让位移和尺寸变化打架。
   锚点必须是左上角，才能和外层 `offset` + `size` 的插值对上。

圆角从 `15dp`（图标圆角）线性收到 `0` —— 窗口"展平"的过程就是它变成全屏的过程。

### 7.2 谁来持有窗口：`IosOpenAppWindow` 的存在理由

```kotlin
/**
 * Keeps the open app's window mounted across the close animation.
 *
 * [IosShellState.openApp] drops to `null` the moment the user goes home, but the window still has
 * to shrink back into its icon before it can be unmounted — so the shell holds its own copy and
 * only clears it once [IosAppWindow] reports that it has finished animating out.
 */
```

**这是"动画比状态活得久"的经典问题**：
用户按 Home → `state.openApp = null` → 如果 UI 直接跟着 `null` 卸载窗口，**动画根本来不及播**，
屏幕会"啪"地回到主屏。

解法是 shell 自己再存一份 `windowApp`，只在 `onFinished()`（窗口已缩回图标）时才清空：

```kotlin
LaunchedEffect(openApp) {
    if (openApp != null) { windowOrigin = state.openAppOrigin; windowApp = openApp }
}
val app = windowApp ?: return
key(app.id) {
    IosAppWindow(app = app, origin = windowOrigin, visible = openApp != null, ...,
        onFinished = { if (state.openApp == null) windowApp = null })
}
```

`key(app.id)` 保证换 App 时窗口重建，而不是复用上一个 App 的动画进度。

**时长**：打开 `420ms`（`EaseOutCubic`），关闭 `300ms`。
打开比关闭慢是手机 UI 的通用规律 —— 打开要"仪式感"，关闭要"利落"。

### 7.3 App 内部换一块 backdrop

窗口是不透明的系统底色（浅色 `0xFFF2F2F7` / 深色 `Color.Black`）。
此时窗口内部的玻璃**不能**再采 `wallpaperBackdrop` —— 光穿不过不透明底，物理上说不通，
看起来就是"玻璃里飘着一些不该看到的东西"。

```kotlin
val appBackdrop = rememberLayerBackdrop()

Box(Modifier.fillMaxSize().background(systemBackground).layerBackdrop(appBackdrop)) {
    // 顶部 320dp 的 App 主题色渐隐
    Box(Modifier.fillMaxWidth().height(320.dp).background(Brush.verticalGradient(
        listOf(app.bottom.copy(alpha = 0.55f), Color.Transparent))))
}
```

然后 App 内所有玻璃采 `appBackdrop`。

> **规律（第 02 章也强调过）**：玻璃要折射的是"它视觉上真正压在什么上面"，
> 而不是"程序里最先录的那一层"。

## 8. 控制中心 / 通知中心

[IosOverlays.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosOverlays.kt)

### 8.1 共享的下拉面板 `IosPullDownPanel`

两层 `AnimatedVisibility`，**分别管遮罩和面板**：

```kotlin
// ① 遮罩：只做淡入淡出
AnimatedVisibility(visible, enter = fadeIn(tween(220)), exit = fadeOut(tween(180))) {
    Box(Modifier.fillMaxSize().background(Color.Black.copy(alpha = 0.3f))
        .clickable(interactionSource = null, indication = null) { onDismiss() })
}

// ② 面板：滑入滑出
AnimatedVisibility(
    visible,
    enter = slideInVertically(tween(320, easing = EaseOutCubic)) { (it * entryOffset).roundToInt() },
    exit  = slideOutVertically(tween(240, easing = EaseOutCubic)) { (it * entryOffset).roundToInt() }
) { ... }
```

`entryOffset = -1f` → 从屏幕上方滑入。**参数化的 `entryOffset` 是为了将来做"从下方来的面板"时能直接复用。**

**退出比进入快（320 → 240）**：进来要有存在感，走要干脆。这条规律在整个外壳里反复出现。

### 8.2 手势收起

```kotlin
private const val DismissThresholdPx = -64f

.draggable(
    orientation = Orientation.Vertical,
    state = rememberDraggableState { delta ->
        scope.launch { dragOffset.snapTo((dragOffset.value + delta).coerceAtMost(0f)) }
    },
    onDragStopped = { velocity ->
        if (dragOffset.value < DismissThresholdPx || velocity < -900f) {
            dragOffset.animateTo(-320f, tween(180, easing = EaseOutCubic))
            onDismiss()
            dragOffset.snapTo(0f)
        } else {
            dragOffset.animateTo(0f, spring(DampingRatioMediumBouncy, StiffnessMediumLow))
        }
    }
)
```

`coerceAtMost(0f)` → 面板**只能往上推**，不能往下拖（和锁屏 `coerceIn` 是同一个道理）。

**注意 `snapTo(0f)` 紧跟在 `onDismiss()` 之后**：面板的 `AnimatedVisibility` 已经在播退出动画了，
如果不复位这个手动的 `dragOffset`，下次打开面板时会带着上次的偏移量出现。

### 8.3 控制中心的内容

```kotlin
GlassControlCenter(backdrop = backdrop, isLightTheme = isLightTheme)
```

材质来自 `GlassOverlays.kt` 的 `GlassControlCenter`（上游 `destinations/ControlCenterContent.kt`）：

```kotlin
val uiSensor = rememberUISensor()          // 加速度计 → 重力方向

val glassHighlight = {
    Highlight(style = HighlightStyle.Default(
        angle = uiSensor.gravityAngle,     // ← 高光跟着手机倾角滑动
        falloff = 2f
    ))
}

// 每个方块
.drawBackdrop(
    backdrop = backdrop,
    shape = { itemShape },
    effects = GlassMaterials.controlCenterItem(1f),   // vibrancy + lens(24, 48, depthEffect)
    highlight = glassHighlight,
    shadow = null,                                    // ← 注意：控制中心方块没有外投影
    onDrawSurface = { drawRect(IosColors.ControlCenterSurface) }   // Black 5%
)
```

三个"苹果味"的细节，都在这里：

| 细节 | 做法 | 为什么 |
|---|---|---|
| 高光跟着重力走 | `angle = uiSensor.gravityAngle` | 手机倾斜时玻璃上的亮光会"滑动"，这是最容易被忽略、但最能骗过眼睛的一条 |
| 染色只有 5% 黑 | `ControlCenterSurface` | 大面板 + 低染色 = 玻璃感；染色一高就变实心块 |
| `shadow = null` | 显式去掉外投影 | 控制中心是"紧贴屏幕的一层"，不是"浮起来的卡片" |

**`shadow = null` 是需要显式写的** —— 不写就用库默认的 `Shadow.Default`（24dp 黑 10%），
大面板上会出现一圈很重的黑影，一眼就假。

### 8.4 通知中心

结构：大时钟 68sp Light + 日期 + 三张 `IosNotificationCard`（默认 `surfaceColor = White 22%`）。

**为什么锁屏是 14%、这里是 22%**：通知中心的背景是"主屏 + 遮罩"，比锁屏的鲜艳壁纸更"实"，
所以需要有更强的底来保证文字可读。这仍然是 04 章"克制阶梯"的取值。

### 8.5 通知卡：锁屏与通知中心共用

```kotlin
fun IosNotificationCard(
    backdrop: Backdrop, app: IosApp, title: String, body: String, time: String,
    modifier: Modifier = Modifier,
    surfaceColor: Color = Color.White.copy(alpha = 0.22f)

```

**共用是对的，差异只有 `surfaceColor` 一个参数** —— 两个界面上的通知卡在真实 iOS 里本来就是同一个组件。
把差异收敛成一个默认参数，比复制两份代码好得多。

## 11. 手势层

[IosShell.kt L199-L268](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt#L199-L268)

### 11.1 顶部两条下拉区

```kotlin
private val PullZoneHeight = 44.dp
private const val PullThresholdPx = 70f

Row(Modifier.fillMaxWidth().height(PullZoneHeight).align(Alignment.TopCenter)) {
```

**中间那 20% 的空 `Spacer` 是整个文件里最重要的一行"留白"**：

阈值：位移 `> 70px` **或** 速度 `> 800px/s` —— 和锁屏一样，位移 + 速度双判据。

### 11.2 底部上滑

```kotlin
private val HomeGestureHeight = 40.dp

onDragStopped = { velocity ->
    val triggered = travel.value < -70f || velocity < -900f
    travel.snapTo(0f)
    if (triggered) state.homeGesture()
}
```

**`travel` 只用来判定，不参与绘制** —— 所以触发后立刻 `snapTo(0f)`，不需要回弹动画。
（对比锁屏：锁屏的 `offsetY` 是**要画出来的**，所以必须 `animateTo` 回弹。）

这个区别值得单独记一笔：**手势状态要不要"可视化"，决定了它是 `Animatable` 还是普通累加器。**

### 11.3 手势去向总表

| 手势 | 位置 | 判据 | 结果 |
|---|---|---|---|
| 上滑 | 底部 40dp | 位移 < -70px 或 速度 < -900px/s | `state.homeGesture()`（三种含义，见 §4.2） |
| 下拉 | 顶部左 40% | 位移 > 70px 或 速度 > 800px/s | 打开通知中心 |
| 下拉 | 顶部右 40% | 同上 | 打开控制中心 |
| 上滑 | 锁屏全屏 | 位移 < -180px 或 速度 < -1100px/s | 解锁 |
| 上滑 | 面板全屏 | 位移 < -64px 或 速度 < -900px/s | 收起面板 |
| 上滑 | 多任务卡片 | 位移 < -150px 或 速度 < -900px/s | 移除该 App |

**所有"位移 + 速度"的双判据，速度阈值都在 800~1100px/s 这个区间。**
这是一个可以直接复用的经验值。

## 12. 主题、配色与壁纸

- `isLightTheme = !isSystemInDarkTheme()`（[IosColors.kt L74-L76](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/core/ios/IosColors.kt#L74-L76)）
- 全部颜色集中在 `IosColors`，逐个标注了上游出处，见 04 章 §3。
- **规律**：`IosColors.content(isLightTheme)` 用于"在玻璃/界面上"的文字；
  锁屏文字**恒白**；灵动岛**恒黑底白字**。

壁纸是**程序化生成的**，不是素材图片（[IosScaffold.kt L33-L118](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosScaffold.kt#L33-L118)）：

```
3 套调色板（深夜蓝紫 / 暖橙玫红 / 青绿）
每套 = 3 色线性渐变底 + 4 个径向渐变的"色球"（位置/半径都用 0..1 相对坐标）
浅色主题：每个色球颜色 lift() —— 向白色混合 34%，保证浅色下玻璃仍然读得出来
```

**为什么不用图片**：
1. 不引入任何第三方美术资源，没有版权问题；
2. 玻璃要折射的正是**高对比、多色、有渐变的对象**，程序化色球刚好能提供这种背景，
   而且换壁纸只要 `state.wallpaper++`（控制中心里那个按钮），零成本。

> 一个实用经验：**评估玻璃效果时，背景一定要有高对比的色块边界。**
> 纯色或灰阶背景上，折射/色散几乎看不出来，会让人误以为"参数没用"。

| 措施 | 位置 | 收益 |
|---|---|---|
| 条件录制（`surfaceIsRead`） | `IosShell` | 主屏日常操作时省掉一次全屏 offscreen pass |
| App 内单独 `appBackdrop` | `IosAppWindow` | 窗口不需要全屏录，只录窗口内那一层 |
| 面板收起时 `if (!visible) return` | `IosAppSwitcher` | 不进入组合 = 不布局不绘制 |
| 手势层条件挂载 | `IosShell` | 锁屏/多任务下不抢手势 |
| 小 `LayerBackdrop` | `GlassControls` 的 `trackBackdrop`（64×28） | 离屏面积 ∝ 成本 |

**最容易忽略的一条**：`IosAppSwitcher` 的第一行就是 `if (!visible) return`。
如果不加，多任务的 `LazyRow` 会在你看不见的时候也参与布局。

## 14. 已知问题与接手建议（诚实清单）

这一节记录**这个外壳目前真实存在的不足**。它们**不是 bug 报告，而是给下一个 AI 的路线图**。

### 14.1 主屏图标用的是矢量线稿，不是"苹果应用图标分区"

**现状**：主屏图标 = 自绘渐变 squircle + [`IosGlyphs`](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosGlyphs.kt) 里的**单色线稿字形**，
字形来自 ui-icons-hub 的 `Lucide` 集合（ISC 许可，SVG）。

**用户的反馈原话**：

> 你这个苹果的应用图标，我给你的那个网站里面不是有单独的苹果应用图标分区吗？你直接拿那个用不就行了吗？

**他说得对。** ui-icons-hub 里确实有一个独立的 `app-icons/` 分区，里面是
**797 张已经切好圆角的 iOS26 风格应用图标 PNG**（不透明区域只有 27MB）。
这才是"苹果应用图标"的正确来源。**完整的接入方案见 [06-图标与资产管线.md](06-图标与资产管线.md) §8。**

### 14.2 锁屏与主屏是"两个兄弟节点叠在一起"

**现状**：[IosShell.kt L110-L115](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosShell.kt#L110-L115)

```kotlin
if (state.isLocked) {
    IosLockScreen(backdrop = overlayBackdrop, onUnlock = { state.unlock() })
}
```

锁屏和主屏在**同一个 `Box` 里同时组合**。锁屏的 `Column` 里全是 `Spacer` 和少量内容，
**主屏就在它下面一层，透过锁屏的空白区域完全可见**；上滑时锁屏整体位移，
主屏一动不动地待在原地 —— 用户的原话：

> 我发现一个问题，那个锁屏界面它和主界面是直接堆叠在一起的就是能在锁屏界面直接看到主界面，
> 然后上滑锁屏界面才消失。

**已经修的**：加了空 `clickable` 吞掉点击（§5.3），所以"看得到"不会变成"点得到"。**只是视觉上仍不对。**

**正确的做法（建议接手方实现）**：

把"锁屏 / 主屏"从"两个并列节点"改成**同一个连续空间的两个状态**，
用一个共享的 `unlockProgress: 0f..1f` 同时驱动两边：

```kotlin
// 解锁进度 0 = 全锁屏，1 = 全主屏
val p = unlockProgress

// 主屏：一直存在，但从"略小 + 略暗"过渡到正常
IosHomeScreen(
    modifier = Modifier
        .graphicsLayer {
            val s = lerp(0.94f, 1f, p)
            scaleX = s; scaleY = s
            alpha = p            // 或 lerp(0f, 1f, p)，取决于想要的观感
        }
)

// 锁屏：盖在上面，整体上移 + 淡出
IosLockScreen(
    modifier = Modifier
        .graphicsLayer {
            translationY = -size.height * EaseOutCubic.transform(p)
            alpha = 1f - p
        }
)
```

配套改动：

1. `IosShellState` 里把 `surface: IosSurface` 换成一个 `unlockProgress: Float`（或保留枚举 + 加一个进度），
   `unlock()` 变成"把进度动画到 1"，动画结束才切 `surface = Home`；
2. 锁屏的 `draggable` 不再自己维护 `offsetY`，而是**直接驱动 `unlockProgress`** ——
   这样手指拖到哪，锁屏就在哪、主屏就同步亮到哪（**跟手**，而不是"松手后才播动画"）；
3. 上滑未过阈值时，`unlockProgress` 用 `spring` 回弹到 0。

**这样"能在锁屏上看到主屏"就不再是问题 —— 因为那本来就是设计意图**：
真实 iOS 解锁时，主屏就是从暗到亮、从略微缩小到正常的。

> 顺带一提：这块改动同时会让 §14.3 的"开机进入锁屏"更自然 —— 因为锁屏不再是"一个可以随便盖上去的页面"了。

### 14.3 没有"开机 → 锁屏"的开机流程

**现状**：[LiquidGlassApp.kt](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/LiquidGlassApp.kt) 是
`液态玻璃启动动画(1.6s) → 1.2s easeOutCubic 交叉过渡 → IosShell`，
而 `IosShell` 的初始状态就是锁屏。**所以"启动页淡出"和"锁屏出现"是同一件事，没有开机过程。**

**用户的反馈原话**：

> 锁屏界面要像正常手机一样，正常手机怎么开机进入锁屏界面的，你就怎么进入。

**建议的真实开机构成**（三段，可以放在 splash 之后）：

| 阶段 | 画面 | 时长 |
|---|---|---|
| 1. 黑屏 | 全黑，无内容 | 300~500ms |
| 2. 开机标志 | 屏幕中央一个 Logo 淡入，然后淡出 | 800~1200ms |
| 3. 锁屏 | 锁屏从"暗"到"亮"（`alpha` 或 `brightness` 0.3 → 1），同时壁纸从略放大到正常 | 400~600ms |

实现建议：在 `LiquidGlassApp` 里加一个 `bootStage` 状态机，
`IosShell` 只在最后一段才被组合；开机那一段**完全不需要 backdrop**（屏幕是黑的），
所以**不会增加任何离屏渲染开销**。

**注意**：不要用苹果的 Logo（商标）。用一个几何图形（圆环 / 抽象苹果形的自绘矢量）即可。

### 14.4 未做真机目视验收

沙箱内没有模拟器 / 真机，**只验证到"编译 → R8 → 打包 → 签名 → AGSL 着色器字符串入库"**，
没有做过帧率与视觉的人工确认。接手方应在 **Android 13+ 真机**（AGSL 需要 API 33+ 才有折射）
上复核，重点看：折射是否跟手、控制中心高光是否随倾角变化、缩放转场是否掉帧。

## 15. 小结

```
①  书写顺序 = z 序。
    壁纸 → 内容层(条件录制) → 状态栏 → 锁屏 → 多任务 → 两个中心 → 手势 → 灵动岛

②  每个玻璃都要回答"我视觉上压在什么之上"：
    Dock → wallpaper    App 内 → appBackdrop    浮层 → combined(wallpaper, surface)

③  覆盖在可交互内容之上的全屏层，必须显式吞掉不处理的手势（空 clickable）。

④  动画比状态活得久 → 用 onFinished 回调决定何时卸载，不要在状态变 null 时立刻卸载。

⑤  只缩放 graphicsLayer、按真实尺寸 requiredSize 布局 → 转场中文字永不重排。

⑥  物理上不存在的东西（挖孔、Home 条）不要套玻璃。

⑦  所有"位移 + 速度"手势，速度阈值都取 800~1100px/s。
```
