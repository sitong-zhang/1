# 01 · 液态玻璃的光学模型

> 这一章回答一个问题：**"玻璃感"到底是由哪些可分离的视觉线索构成的？**
> 只有把这几条线索拆开，你才知道每一个 API 参数在负责哪一条，才不会出现"调了半天，就是不像"。

---

## 1. 真实玻璃有 6 条视觉线索，一条都不能少

拿一块真实的毛玻璃（比如 iPhone 背板上的摄像头玻璃）放在眼前，你看到的是 6 件事同时发生：

| # | 线索 | 物理原因 | 缺了会怎样 |
|---|---|---|---|
| 1 | **背景变形** | 光在介质界面发生折射，玻璃是"透镜"，把背后的东西缩小/错位/拉伸 | 缺 → 看起来像一张贴纸 |
| 2 | **背景模糊** | 表面粗糙 + 厚度导致散射 | 缺 → 背景太清楚，像隐形了 |
| 3 | **色散（彩边）** | 不同波长折射率不同（红光偏折小于蓝光） | 缺 → 在**运动时**会显得"没厚度" |
| 4 | **边缘高光** | 边缘掠射角大，反射率高（菲涅尔效应） | 缺 → 缺了"玻璃存在"的最强暗示，像抠图 |
| 5 | **外投影** | 玻璃有厚度，遮光 | 缺 → 玻璃"浮不起来"，贴在背景上 |
| 6 | **自身染色** | 玻璃本身有色/有反射 | 缺 → 太"空"，但不该多（见下） |

**关键洞察：这 6 条里，1、2、3、6 是"透过玻璃看背景"，4、5 是"玻璃本体的存在感"。**

苹果做得好，不是因为它把这 6 条做得多强，而是**每一条都刚好够用，而且第 6 条非常克制**。
绝大多数仿制品失败在第 6 条——把玻璃画成了半透明的白块。

---

## 2. 六条线索 → 六个 API

| 线索 | API | 所在位置 |
|---|---|---|
| ① 背景变形 | `lens(refractionHeight, refractionAmount, chromaticAberration, depthEffect)` | `effects` 里的**最后一行** |
| ② 背景模糊 | `blur(radius)` | `effects` 里的**倒数第二行** |
| ③ 色散 | `lens(..., chromaticAberration = true)` | 同一个 `lens` 调用 |
| ④ 边缘高光 | `highlight = { Highlight(...) }` | `drawBackdrop` 的独立参数 |
| ⑤ 外投影 | `shadow = { Shadow(...) }`（内暗边用 `innerShadow`） | `drawBackdrop` 的独立参数 |
| ⑥ 自身染色 | `onDrawSurface = { drawRect(color) }` | `drawBackdrop` 的独立参数 |
| （提亮校正）| `vibrancy()` / `colorControls(brightness, saturation)` | `effects` 里的**第一行** |

```kotlin
Modifier.drawBackdrop(
    backdrop = backdrop,
    shape = { RoundedRectangle(24.dp) },
    effects = {
        vibrancy()                      // ⑦ 颜色校正（校正 ② 带来的灰）
        blur(8f.dp.toPx())              // ② 背景模糊
        lens(24f.dp.toPx(), 24f.dp.toPx(), chromaticAberration = false)  // ①③ 折射 + 色散
    },
    highlight = { Highlight.Default },  // ④
    shadow = { Shadow.Default },        // ⑤
    innerShadow = { ... },              // ⑤'
    onDrawSurface = { drawRect(Color.White.copy(alpha = 0.22f)) }  // ⑥
)
```

**每个参数只负责一条线索。** 想清楚"我现在缺的是哪一条"，再去改对应的参数，
不要瞎调 `lens` 的两个数字。

## 3. 为什么管线顺序是 `colorFilter → blur → lens`（不可换）

这不是风格问题，是**数学上必须**：

```
原始背景纹理
   │
   ├─ ① colorFilter / vibrancy / colorControls
   │     在"清晰的原始像素"上做颜色变换。此时像素还一一对应，做颜色矩阵最准。
   │
   ├─ ② blur
   │     对颜色变换后的画面做卷积。模糊半径越大，采样范围越广。
   │
   └─ ③ lens
         对"已经模糊好的画面"做几何采样偏移。
         如果把 lens 放到 blur 前面：先折射 → 折射后在采样边界外产生越界像素
         → 再 blur 时越界像素被抹开 → 边缘出现一条脏边/发白发糊。
```

**工程结论：`effects` 代码块里的书写顺序就是执行顺序，`lens` 必须是最后一行。**
仓库里 `GlassMaterials.kt` 的 12 个配方无一例外遵守这个顺序。

> 补充：如果你需要极端的颜色控制，还有 `colorFilter(ColorFilter)` 和 `opacity(alpha)`，
> 它们和 `vibrancy()` 同属第一阶段。

## 4. `lens()` 的两个参数到底在调什么

这是整套方案里最需要建立直觉的地方。

### 4.1 参数语义

```kotlin
lens(
    refractionHeight = 24f.dp.toPx(),   // 第一个参数
    refractionAmount = 48f.dp.toPx(),   // 第二个参数
    chromaticAberration = false,
    depthEffect = false
)
```

把玻璃想象成一块**边缘隆起、中间平坦的透镜**（苹果的 Liquid Glass 就是这样建模的）：

| 参数 | 直觉模型 | 变大时 | 变小时 |
|---|---|---|---|
| `refractionHeight`（折射高度） | 透镜"隆起"的**高度**，决定折射从边缘向内的**作用范围有多宽** | 折射带变宽，整块玻璃都在扭，像一颗厚水滴 | 折射带变窄，只有贴边 1~2mm 有变形 |
| `refractionAmount`（折射量） | 最大的**像素位移量**，决定扭得**有多狠** | 背景被推得更远，更"凸"、放大感更强 | 更平，接近普通模糊玻璃 |

**经验法则：**

```
refractionAmount ≈ 2 × refractionHeight
```

仓库里所有配方都遵循这个比例（`12/24`、`24/24`、`24/48`、`16/32`、`10/14`……第二个略大于或等于第一个的 2 倍）。
**自己推导新配方时，先按 2:1 起手，再微调。** 详见 `04-材质配方表.md`。

### 4.2 为什么必须是 `dp.toPx()`

`lens` 的参数单位是**像素**（`Float`，屏幕物理像素）。
你写 `24f` 而不 `toPx()`，在 3x 屏上折射只有应该有的 1/3 —— 这正是很多人"参数照抄了但效果不对"的原因。

**规则：凡是传给 `blur()` / `lens()` / `Highlight(width=)` / `Shadow(radius=)` 的长度，一律 `dp.toPx()`。**

例外：`InnerShadow(radius = 8f.dp * progress)` 这种在 `drawBackdrop` 的 lambda 里，
`BackdropEffectScope` 本身就是 `Density`，可以 **直接用 `8f.dp.toPx()`**——所以上游代码里两种写法都出现过，
`GlassMaterials.kt` 里统一用 `.toPx()`。

### 4.3 `depthEffect`

打开后，折射方向从"平面内的位移"变成带"纵深"的球面映射——玻璃中间会显得更"鼓"。
上游只用在大面积、强暗示的材质上：**弹窗（dialog）**和**控制中心**。
小控件不要开，会显得扭曲。

### 4.4 `chromaticAberration` —— 只在动的时候开

物理上，色散 = R/G/B 三通道用**略微不同的偏移量**采样。静止时人眼很容易识破（"这玻璃边缘怎么永远有彩边"）。

上游的统一做法是把色散绑到一个 `progress`：

```kotlin
// 上游 components/LiquidBottomTabs.kt —— 移动中的选中指示器
fun selectionIndicator(progress: Float): BackdropEffectScope.() -> Unit = {
    lens(
        10f.dp.toPx() * progress,
        14f.dp.toPx() * progress,
        chromaticAberration = true     // 常开，但整体强度随 progress → 0
    )
}
```

`progress` 来自按压进度或拖动进度，静止时 `progress = 0`，`lens(0, 0)` 等于什么都没做，色散自然消失。

**这就是"苹果味"的核心：所有夸张的光学效应都只在交互瞬间出现。**

## 5. `vibrancy()` —— 最容易被忽略、但决定成败的一行

高斯模糊在数学上是**低通滤波**：它抹掉高频（细节），同时**降低局部对比度和感知饱和度**。
结果就是：模糊后的背景会**发灰**。

`vibrancy()` 做的事就是补偿这个：**提高饱和度 + 轻微提升亮度**，把"灰色玻璃"变回"透亮的玻璃"。

对比：

```kotlin
// ❌ 灰扑扑，像磨砂塑料
effects = { blur(16f.dp.toPx()); lens(24f.dp.toPx(), 48f.dp.toPx()) }

// ✅ 透亮，像真的玻璃
effects = { vibrancy(); blur(16f.dp.toPx()); lens(24f.dp.toPx(), 48f.dp.toPx()) }
```

需要**更精细**的控制时，用 `colorControls` 的显式参数（上游弹窗就是这么做的）：

```kotlin
colorControls(
    brightness = if (isLightTheme) 0.2f else 0f,
    saturation = 1.5f
)
```

- 浅色主题：背景亮 → 提亮 0.2，饱和 1.5（否则白玻璃看起来是灰的）
- 深色主题：背景暗 → 不提亮，只提饱和（再提亮就爆了）

**记住这条对应关系：`blur` 越大，越需要 `vibrancy` 兜底。**

## 6. `Highlight` —— 玻璃"存在感"的来源

### 6.1 它是什么

不是描边。它是**沿形状轮廓、按指定角度、向内渐隐的一条高光带**。

```
        ┌─────────────────────┐
        │  ╭───────────────╮  │   ← 高光带（宽 width、柔化 blurRadius、
        │  │               │  │      透明度 alpha、衰减曲线 falloff）
        │  │    玻璃内部    │  │
        │  ╰───────────────╯  │
        └─────────────────────┘
         ↑ 高光只出现在"迎着光"的那一侧，随 angle 旋转
```

### 6.2 三个可用预设

| 预设 | 含义 | 用在哪 |
|---|---|---|
| `Highlight.Default` | 默认方向（左上打光的斜向高光） | 绝大多数组件，省略该参数时库自动用它 |
| `Highlight.Ambient` | 环境光（更均匀、更弱） | 大面积平板，避免出现明显的单向亮边 |
| `Highlight.Plain` | 极简 | 需要几乎无高光时 |

`Highlight.Default.copy(alpha = progress)` 是最常见的写法：**按下时高光变强**。

### 6.3 重力高光 —— 苹果味的关键细节

上游控制中心的写法：

```kotlin
val uiSensor = rememberUISensor()      // 加速度计 → 重力方向

val glassHighlight = {
    Highlight(
        style = HighlightStyle.Default(
            angle = uiSensor.gravityAngle,   // ← 高光方向跟随手机倾角
            falloff = 2f                     // ← 衰减曲线，越大越"收得快"
        )
    )
}
```

`gravityAngle` 由 `TYPE_ACCELEROMETER` 的 `atan2(y, x)` 平滑得到（`alpha = 0.5f` 的一阶低通），
初始值 `45f`。**手机倾斜时，玻璃上的高光会跟着"滑动"** —— 这是让人一眼觉得"真"的隐藏细节。

实现见 `core/utils/UISensor.kt`（上游 `utils/UISensor.kt` 的 1:1 移植）。

> 已有 `InteractiveHighlight`（`core/utils/InteractiveHighlight.kt`）用于"手指按住的位置产生局部高光"，
> 上游底栏的选中指示器在用。

### 6.4 不要用 `border()`

```kotlin
// ❌ 均匀硬边，像塑料相框
Modifier.border(1.dp, Color.White.copy(alpha = 0.3f), RoundedCornerShape(24.dp))

// ✅ 迎着光的一侧有亮边，另一侧没有
highlight = { Highlight.Default }
```

## 7. `Shadow` 与 `InnerShadow`

| 参数 | 作用 | 典型值 |
|---|---|---|
| `shadow` | 外投影，给玻璃"厚度"和"浮起感" | 库默认 `Shadow.Default`；动效里常写 `Shadow(alpha = progress)` |
| `innerShadow` | 内阴影，在玻璃内侧边缘压一圈暗，模拟**切面厚度** | `InnerShadow(radius = 8f.dp * progress, alpha = progress)` |

`innerShadow` 是"高级感"的隐形来源：玻璃边缘如果只有亮线没有暗边，会显得很薄、像纸片。
**亮边 + 内暗边 = 有厚度的实体。**

上游只在**被按下的动态态**加 `innerShadow`（`progress` 从 0 → 1），静止态不加，避免脏边。

## 8. 六条线索的"配比表"（为什么苹果看起来贵）

| 线索 | 苹果的强度 | 常见仿制品 | 后果 |
|---|---|---|---|
| 背景模糊 | 克制，2~16dp，看尺寸定 | 一上来 40dp | 背景全糊成一片，玻璃变"果冻" |
| 折射 | 明确，且与尺寸成比例 | 完全不折射或折射过头 | 前者是贴纸，后者是哈哈镜 |
| 色散 | 只在运动中，很弱 | 常开、很强 | 廉价彩边 |
| 边缘高光 | 柔和，宽度 1~2dp 视觉量级，有衰减 | 1px 硬白描边 | 塑料框 |
| 外投影 | 很弱、很大扩散 | 深黑硬阴影 | 贴纸 |
| 自身染色 | **5%~35%** | 60%+ 白 | 白卡片，不是玻璃 |

**一句话：把 ⑥ 压到最低，把 ①④ 做对，其余跟着走。**

## 9. 反例清单（这些做法一定不像）

| ❌ 做法 | 为什么错 |
|---|---|
| `Modifier.background(Color.White.copy(0.3f))` + `Modifier.blur()` | 模糊的是**自己**，不是背景。这是磨砂塑料 |
| `Modifier.alpha(0.5f)` | 半透明 ≠ 玻璃，没有折射、没有高光、没有边缘 |
| `border(1.dp, Color.White)` | 均匀硬边 |
| `RoundedCornerShape(24.dp)` | 普通圆角，不是 G2 连续曲率 |
| 手写 `RenderEffect.createBlurEffect` | 只有模糊，丢了折射/色散/高光，而且没有"背景纹理"的概念 |
| 用两张图片叠一叠 | 背景一滚动就穿帮 |
| `lens(24f, 48f)` 不 `toPx()` | 参数在 3x 屏上只有 1/3 强度 |
| 给整屏都套玻璃 | 玻璃是"局部强调材料"，全屏都是玻璃 = 没有对比 = 不高级 |

## 10. 本章小结

```
真实感 = 折射(①) 说"这有块玻璃"
       + 模糊(②) 说"玻璃是磨砂的"
       + 高光(④) 说"光在这反弹了"
       + 投影(⑤) 说"玻璃有厚度"
       + 染色(⑥) 说"玻璃有颜色"——但只说一点点
       + 色散(③) 说"玻璃在动"
```
