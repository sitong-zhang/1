# 06 · 图标与资产管线

> 这一章解决一个很具体的问题：**`ui-icons-hub` 这个仓库该怎么用。**
>
> 它里面其实有**两条完全不同性质的资产管线**，混用会出事：
>
> | 管线 | 位置 | 内容 | 性质 |
> |---|---|---|---|
> | **A · SVG 图标集** | `data/` + `index.json` | 215 个开源图标集 / 34 万+ 个 SVG | 矢量、单色线稿，需要转成 `ImageVector` |
> | **B · 苹果应用图标分区** | `app-icons/` | **797 张 iOS26 风格应用图标 PNG** | 位图、已经切好圆角、自带品牌色 |
>
> 本仓库的**外壳当前用的是 A 管线**（`Lucide` 线稿）；
> 而**主屏 App 图标本来应该用 B 管线**（苹果应用图标分区）。
> 这一章把两条都讲透，并在 §8 给出从 A 切到 B 的完整可执行方案。

## 1. `ui-icons-hub` 仓库是什么

- 仓库：<https://github.com/sitong-zhang/ui-icons-hub>
- 在线站点：<https://sitong-zhang.github.io/ui-icons-hub/>
- 一句话：把散落在 GitHub 上的开源图标库**聚合、归一化、分块**，配一个**能理解中文意图**的搜索（FlexSearch，Apache-2.0）。

### 1.1 与本工程相关的目录

| 路径 | 内容 | 我们用不用 |
|---|---|---|
| `data/` | 图标数据分块，**按需懒加载**（每个集合若干 `__N.js`） | ✅ A 管线的原料 |
| `index.json` / `index-compact.json` | 全部集合的索引（8.3 MB，含 SVG 外层包装信息 viewBox 等） | ✅ 生成脚本读 `viewBox` |
| `icons.js` | `window.ICON_SETS`：215 个集合的元数据（许可、主页、数量、svg wrapper） | 参考 |
| `app-icons/` | **iOS26 风格应用图标分区：797 张 PNG** | ⭐ B 管线（§2） |
| `search.js` / `search-data.js` | 搜索实现与轻量索引 | ❌ |
| `cdn.js` | 零依赖浏览器 SDK（`<script>` 一行接入） | ❌ |
| `mcp/` / `packages/` / `skill/` | MCP server / npm 包 / AI skill | ❌ |
| `skills/` | 设计技能分区（软件 / 网站 / 游戏） | ❌ |

### 1.2 数据块的格式（**读 A 管线代码前必须知道**）

`data/<slug>__<n>.js` 里的内容**不是合法 JSON**，而是给浏览器执行的 JS。实测原文形如：

```js
window.__ADD2("lucide-icons__lucide",0,[["phone","<path d=\"...\"/>"],["message-circle","<path .../>"], ...]);
```

要点：

1. 前缀是 `window.__ADD2(`，其后是 `(setSlug, chunkIndex, payloadArray, ...)`；
2. **真正的图标数组从第一个逗号之后开始**，到本行的最后一个 `]` 结束；
3. 每个元素是 **`[名字, SVG 内部标记, ...可选元数据]`** —— 第 3 项之后可能有额外字段，
   **所以不能用 `for name, markup in ...` 去解包**（这正是下面 §4.4 的坑 2）。

> **`ui-icons-hub` 自己提供了 `cdn.js` / `packages/` / `skill/` 三条正规接入通道。**
> 本工程要的是"把图标**编译期**编进 APK"，所以选择**直接读 `data/` 原始分块**，
> 这是一个刻意的取舍：换来零运行时依赖和零网络请求。

## 2. 苹果应用图标分区 `app-icons/`（**实测盘点**）

这一节的数字全部是在本机对真实文件跑出来的，不是估计。

### 2.1 目录结构

```
ui-icons-hub/app-icons/
├── index.html        52528 B   ← 分区页面（"iOS26 · 苹果风格应用图标分区 · Farewell UI 图标库"）
├── icons.js          9751  B   ← 清单：window.APP_ICONS=[{"n":名,"f":相对路径,"src":id}, ...]
├── rename_map.json   24246 B   ← { "icon83676d51": "Aima", ... }  id → 名称
└── png/              27 MB     ← 797 个 PNG 本体
```

页面 `<title>` 与页脚原文：

```html
<title>iOS26 · 苹果风格应用图标分区 · Farewell UI 图标库</title>
<meta name="description" content="iOS26 风格应用图标包全量收录 · 797 个应用图标（PNG），苹果 iOS 圆角风格" />
...
<footer>Farewell UI 图标库 · iOS26 应用图标分区 · 数据来源：iOS26 图标包（开源）</footer>
```

### 2.2 `icons.js` 的格式

```js
window.APP_ICONS=[{"n":"Aima","f":"png/Aima.png","src":"icon83676d51"},
                  {"n":"Bank Sdnxs","f":"png/Bank%20Sdnxs.png","src":"icon049e4ce7"}, ...]
```

| 字段 | 含义 |
|---|---|
| `n` | 显示名（**含中文**，例如 `人人视频`、`录音`、`兴业银行`、`红果`） |
| `f` | 相对 `app-icons/` 的路径，**含空格的文件名被 URL 编码为 `%20`** |
| `src` | 图标 id，可到 `rename_map.json` 反查名称 |

**解析时要注意**：`f` 是 **URL 编码**过的，拿去当文件路径前要先 `urllib.parse.unquote`。

### 2.3 实测统计（跑出来的）

**数量**：797 个 PNG，合计 **27 MB**。

**尺寸分布 —— 不统一，这是接入时第一个必须处理的点**：

| 像素 | 数量 |
|---:|---:|
| 214 × 214 | 506 |
| 216 × 216 | 234 |
| 400 × 400 | 56 |
| 595 × 595 | 1 |

**色彩格式**：`8-bit/color RGBA`（colortype 6，带 alpha 通道）。

**圆角状态 —— 已经切好了，不要再切**：
实测 `Camera.png` / `Toutiao.png` / `Aima.png` 的**四角 alpha 均为 0**（透明），
沿顶行第一个不透明像素出现在 `x ≈ 58`（214 宽）。即：

> **这些 PNG 本身就是"苹果 iOS 圆角风格"的成品图标**（预切圆角 + 透明角），
> 圆角半径约为边长的 **27%**（214 的 58/214）。
>
> 所以贴到界面上时：
> - ✅ `Image(painterResource(...), Modifier.size(62.dp))` —— 直接用；
> - ❌ **不要**再 `.clip(RoundedRectangle(15.dp))` —— 二次圆角只会把图标切掉一圈，
>   而且半径几乎不可能和素材自带的对上；
> - ⚠️ 如果一定要加阴影，`Modifier.shadow(elevation, shape = RoundedRectangle(内建半径), clip = false)`，
>   半径取值要按 **0.27 × 边长** 估（62dp 图标 → ≈ 16.7dp），并肉眼校一次。

### 2.4 许可提醒（**发布前必看**）

- `ui-icons-hub` 的 README 第一段就写明：
  > Icon artwork remains the property of each upstream project. This site ships **no unified license** for the assets — always check each collection's own upstream license.

- 而 `app-icons/index.html` 只写了"数据来源：iOS26 图标包（开源）"，
  **没有**给出这个图标包的具体上游许可证。
- 这 797 个是**真实应用的品牌图标**（淘宝、抖音、银行、游戏……）。

**结论：把 `app-icons/` 的 PNG 打包进要发布的 App 之前，必须自行确认授权。**
本仓库当前**没有**把任何 `app-icons/` 的图片复制进工程，正是出于这个原因。
做**本地演示 / 个人测试**是一回事，**上架发布**是另一回事。

## 3. 当前实现用的是哪条管线（现状说明）

**主屏图标的构成 = 自绘渐变 squircle + 单色矢量字形。**

```
┌──────────────────────────┐
│  Box(62dp, RoundedRectangle(15dp))          ← 自绘
│    background = 双色线性渐变 (app.top → app.bottom)   ← 自绘（IosAppCatalog 里定的）
│    shadow(10dp, 黑 40%)                      ← 自绘
│    ┌────────────────┐                        │
│    │  GlassIcon(31dp)│  ← IosGlyphs 的白色线稿字形（A 管线 / Lucide）
│    └────────────────┘                        │
└──────────────────────────┘
```

- **字形来源**：[`IosGlyphs.kt`](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosGlyphs.kt)，
  **68 个** `ImageVector`，由 `tools/generate_ios_glyphs.py` 从
  `data/lucide-icons__lucide__{0,1}.js`（Lucide，**ISC 许可**）生成。
- **渐变配色**：`IosAppCatalog.kt` 里每个 App 手写一组 `top/bottom`，**属于本工程的装饰，不含任何 Apple 美术**。

**优点是**：矢量、极小（几十 KB）、任意缩放不糊、许可干净、零运行时依赖。
**缺点是**：**它不是"苹果应用图标"** —— 它是一套通用线稿图标，配了 iOS 风格的容器。
这正是用户指出"应该直接用 `app-icons/` 那个分区"的原因。

## 4. A 管线：`tools/generate_ios_glyphs.py` 逐段拆解

文件：[`../LiquidGlassShowcase/tools/generate_ios_glyphs.py`](../LiquidGlassShowcase/tools/generate_ios_glyphs.py)

用法：

```bash

    --hub /path/to/ui-icons-hub \
    --out app/src/main/java/com/liquidglass/showcase/ios/IosGlyphs.kt
```

### 4.1 `ICONS`：Kotlin 标识符 → 上游图标名

```python
ICONS: list[tuple[str, str]] = [
    ("Phone", "phone"), ("Messages", "message-circle"), ("Safari", "compass"),
    ("Camera", "camera"), ("Photos", "image"), ("Settings", "settings"),
    ...
    ("X", "x"), ("Plus", "plus"), ("Check", "check"), ("Trash", "trash"),
]
```

按用途分组（主屏/Dock、锁屏、状态栏、控制中心、媒体/杂项），共 68 项。

> **踩过的坑**：这里最初写的是 `trash-2`，但 Lucide 的这个集合里没有 `trash-2`，只有 `trash`。
> 生成脚本对找不到的名字**不报错退出，只收集到 `missing` 列表并打印**，
> 所以第一版产物里少了一个图标而我一开始没注意。
> **教训：生成脚本跑完一定要看最后那行 `MISSING:`。**

### 4.2 `load_set`：从 JS 分块里取出 `{名字: SVG 标记}` 和 `viewBox`

```python
def load_set(hub: Path, slug: str) -> tuple[dict[str, str], str]:
    names: dict[str, str] = {}
    view_box = "0 0 24 24"
    index = json.loads((hub / "index.json").read_text(encoding="utf-8"))
    for entry in index["sets"]:
        if entry["slug"] == slug:
            found = re.search(r'viewBox="([^"]+)"', entry.get("wrap", ""))
            if found:
                view_box = found.group(1)
            break

    for path in sorted((hub / "data").glob(f"{slug}__*.js")):
        text = path.read_text(encoding="utf-8")
        for chunk in text.split("window.__ADD2(")[1:]:
            start = chunk.index(",") + 1
            payload = chunk[start : chunk.rindex("]") + 1]
            for entry in json.loads(payload):
                names[entry[0]] = entry[1]
    return names, view_box
```

四个关键点，**每一条都是踩出来的**：

1. **`viewBox` 从 `index.json` 的 `sets[].wrap` 里正则取**。
   因为 `data/*.js` 里存的只是 `<path>` 之类的内部标记，**不含外层 `<svg viewBox>`**。
2. **`text.split("window.__ADD2(")[1:]`** —— 一个文件里可能有多行 `window.__ADD2` 调用，
   全部拆出来逐个处理（`lucide-icons__lucide` 实际有 `__0.js` / `__1.js` 两个文件）。
3. **`start = chunk.index(",") + 1`** —— 跳过 `"slug",chunkIndex,` 这一段，**从数组的 `[` 开始**。
   第一版写成从头解析，直接 `json.decoder.JSONDecodeError: Extra data: line 1 column 22`。
4. **`chunk.rindex("]") + 1`** —— 用**最后一个** `]` 而不是第一个，才能把整个数组切出来。

### 4.3 `collect_paths`：递归遍历 SVG，保留 fill / stroke

```python
def walk(node, inherited):
    here = {**inherited, **node.attrib}          # ← 属性向下继承（SVG 的 <g fill=...> 靠这个）
    tag = node.tag.replace(f"{{{SVG_NS}}}", "")
    if tag not in ("svg", "g", "defs", "title", "desc", "style", "clipPath"):
        d = to_path(node, here)
        if d:
            is_filled = (here.get("fill") or "").lower() not in ("", "none")
            stroke = (here.get("stroke") or "").lower()
            stroked = stroke not in ("", "none")
            width = _num(here.get("stroke-width"), 2.0)
            out.append((d, is_filled, width if stroked else 0.0))
    for child in node:
        walk(child, here)                        # ← 必须递归所有子节点
```

> **踩过的坑 3**：最初只处理"直接子节点"，遇到 `<g>` 包裹的图标就**一个 path 都取不到**，
> 生成出来的 `ImageVector` 是空的（编译通过、运行时图标不可见）。
> **修法就是"递归全树 + 属性继承"这两件事**。

`to_path` 负责把非 `path` 的基础图形转成等价的 `d`：

| SVG 元素 | 转换 | 备注 |
|---|---|---|
| `path` | 直接用 `d` | |
| `circle` | 用两段半圆弧拼成闭合路径 | `_ellipse(cx, cy, r, r)` |
| `ellipse` | 同上 | |
| `rect` | 生成带 `A`（弧）的圆角矩形路径 | `rx/ry` 会被 `min(rx, w/2)` 夹住 |
| `line` | `M…L…` | |
| `polyline` / `polygon` | `M…L…`（polygon 补 `Z`） | 坐标对按空格/逗号切分 |

### 4.4 生成产物长什么样

```kotlin
/** ui-icons-hub `lucide/phone` */
val Phone: ImageVector = build(
    "Phone",
    listOf(
        Triple("M13.832 16.568a1 1 0 0 0 1.213-.303l.355-.465A2 2 0 0 1 17 15h3a2 2 0 0 1 2 2v3a2 2 0 0 1-2 2A18 18 0 0 1 2 4a2 2 0 0 1 2-2h3a2 2 0 0 1 2 2v3a2 2 0 0 1-.8 1.6l-.468.351a1 1 0 0 0-.292 1.233 14 14 0 0 0 6.392 6.384", false, 2f),
        ...
    )
)
```

`build()` 的关键是**只用 `addPath(pathData = addPathNodes(d), ...)` 这个重载**：

```kotlin
addPath(
    pathData = addPathNodes(data),
    fill = if (filled) SolidColor(Color.White) else null,
    stroke = if (strokeWidth > 0f) SolidColor(Color.White) else null,
    strokeLineWidth = strokeWidth,
    strokeLineCap = StrokeCap.Round,
    strokeLineJoin = StrokeJoin.Round
)
```

两个必须知道的点：

1. **填充/描边颜色统一写死 `Color.White`，不是错误** ——
   最终颜色由 `GlassIcon` 的 `ColorFilter.tint(tint)` 在上层染色，
   这样一套字形可以在任意颜色下复用（白图标、深色图标、强调色图标都用同一个 `ImageVector`）。
2. **`addPathNodes(String)` 是必须的**：Compose 1.12 起 `ImageVector.Builder.path(pathData = ...)`
   重载已不可用，只剩 `path(pathBuilder)`。详见 [07-构建与排错.md](07-构建与排错.md)。

文件头也写明了它不可手改：

```kotlin
/**
 * GENERATED FILE — do not edit by hand. Regenerate with `tools/generate_ios_glyphs.py`.
 */
```

### 4.5 `viewBox` 必须是 24×24

```python
if view_box != "0 0 24 24":
    raise SystemExit(f"unexpected viewBox {view_box!r}; adjust VIEWPORT in the template")
```

**这是刻意的"快速失败"**：`IosGlyphs` 里的 `VIEWPORT = 24f` 是写死的，
如果换了一个 `viewBox` 不是 24 的集合（比如 32、48），坐标会全部错位。
**与其静默画出错误的图，不如直接退出。**

## 5. SVG → Compose `ImageVector` 的通用坑

| 坑 | 现象 | 修法 |
|---|---|---|
| `Builder.path(pathData = ...)` 不存在 | 编译报错 | 用 `addPath(addPathNodes(d), …)` |
| 只填 `fill` 不填 `stroke`（或反之） | 图标全黑 / 完全不可见 | Lucide 是**线稿**，必须给 `stroke` + `strokeLineWidth` + `StrokeCap/Join.Round` |
| `viewBox` 不是 24×24 | 图形被裁切或缩得很小 | 改 `VIEWPORT`，或在生成期做坐标缩放 |
| 忘了递归 `<g>` | 编译通过但图标是空的 | 递归 + 属性继承（§4.3） |
| 颜色写死在 path 上 | 换主题不生效 | 统一 `Color.White` + `ColorFilter.tint` |
| `stroke-width` 缺失 | 线太粗/太细 | 默认值 `2.0f`（Lucide 的常用值） |

## 6. 图标目录与配色：`IosAppCatalog`

[`IosAppCatalog.kt`](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/ios/IosAppCatalog.kt)

```kotlin
data class IosApp(

```

| 分组 | 数量 | 内容 |
|---|---:|---|
| `dock` | 4 | 电话 / Safari / 信息 / 音乐 |
| `page1` | 20 | 日常类（FaceTime、日历、照片、相机、邮件、备忘录、提醒、时钟、地图、天气、新闻、股市、图书、App Store、健康、钱包、文件、播客、TV、家庭） |
| `page2` | 16 | 工具类 + **组件画廊**（设置、计算器、组件画廊、提示、翻译、测距仪、快捷指令、健身、语音备忘录、放大器、浏览器、手电筒、耳机、计时器、闹钟、声音与触感） |

- **浅底图标必须覆写 `glyphTint`**，否则白字形在白底上消失：

| App | 底色 | `glyphTint` |
|---|---|---|
| 日历 | 白 → 灰白 | `#E0342B`（红） |
| 备忘录 | 米黄 → 黄 | `#6B5200`（深棕） |
| 提醒事项 | 白 → 灰白 | `#3A3A3C`（深灰） |
| 提示 | 黄 → 橙 | `#5A3D00` |
| 健身 | 亮绿 → 绿 | `#00401A` |
| 测距仪 | 浅灰 → 中灰 | `#3A3A3C` |
| 手电筒 | 白 → 浅灰 | `#3A3A3C` |

## 7. `GlassIcons.kt`：零依赖的自绘组件图标

[`GlassIcons.kt`](../LiquidGlassShowcase/app/src/main/java/com/liquidglass/showcase/core/ios/GlassIcons.kt)（36 个字形）

**为什么自绘**：原来的方案是 `androidx.compose.material:material-icons-extended`，
但该库**已停止更新**（版本冻结在 1.7.8），与用户的"只用活跃维护依赖"要求冲突，所以弃用。

实现极简，两个私有工厂 + 一堆常量：

```kotlin
private const val STROKE_WIDTH = 1.8f

private fun strokeIcon(name: String, vararg paths: String): ImageVector   // 线稿图标
private fun filledIcon(name: String, vararg paths: String): ImageVector   // 实心图标
```

同样遵循"路径用白色、颜色靠 `ColorFilter.tint`"的约定，
所以同一个字形可以同时给浅色主题（黑）和深色主题（白）用。

**两个图标集的定位不要混**：

| 文件 | 用途 | 数量 | 来源 |
|---|---|---:|---|
| `ios/IosGlyphs.kt` | **App 图标**（主屏/锁屏/灵动岛） | 68 | 生成（A 管线，Lucide） |
| `core/ios/GlassIcons.kt` | **组件图标**（26 个展示组件里的箭头、搜索、勾…） | 36 | 手写 |

## 8. ⭐ 切换到"苹果应用图标分区"的完整方案

这一节是给**接手方**的施工图。目标是：**把主屏图标从"自绘渐变 + 线稿字形"换成 `app-icons/` 的真实 PNG。**

### 8.1 先想清楚三件事

| 问题 | 结论 |
|---|---|
| 797 张全要吗？ | **不要。** 27 MB 全量打包 × 每种像素密度，APK 会变得很大。**只挑主屏用得到的那 40 个**，或按需扩展。 |
| 尺寸统一吗？ | **不统一**（214/216/400/595）。**必须先归一到同一尺寸**，否则视觉大小不一。 |
| 要再切圆角吗？ | **不要。** PNG 自带圆角 + 透明角（§2.3）。 |

### 8.2 命名映射（必须做）

`app-icons` 的名字是**给人看的**（含空格、含中文、URL 编码），
而 Android `res/drawable` 的文件名只能是小写字母、数字、下划线。

所以需要一张显式的映射表。建议的映射（本工程主屏的 40 个 App）：

| `IosAppCatalog.id` | app-icons 里的候选名（`icons.js` 的 `n`） | drawable 名 |
|---|---|---|
| `phone` | `Phone` / `Phone Vivo` | `ic_app_phone` |
| `safari` | `Browser` / `Rains Browser` | `ic_app_browser` |
| `messages` | `Ding Talk` / … | `ic_app_messages` |
| `music` | `Poweramp` / `Netease Ucmooc`… | `ic_app_music` |
| `camera` | `Camera` | `ic_app_camera` |
| `photos` | — | `ic_app_photos` |
| `settings` | — | `ic_app_settings` |

> ⚠️ 上表右侧是**示例性的**，不是权威清单 —— 797 个名字里未必正好有 iOS 原生 App。
> **接手方要做的第一件事，是把 `app-icons/icons.js` 打印成人可读的清单，再逐个挑选。**

### 8.3 第一步：把 `icons.js` 导成清单

```python
# tools/list_app_icons.py  —— 只是查看，不修改任何文件
import json, pathlib, urllib.parse

t = pathlib.Path("app-icons/icons.js").read_text(encoding="utf-8")
data = json.loads(t[len("window.APP_ICONS="):].rstrip().rstrip(";"))
print(f"total = {len(data)}")
for e in sorted(data, key=lambda x: x["n"].lower()):
    print(f'{e["n"]:<42} {urllib.parse.unquote(e["f"])}')
```

> **坑**：`icons.js` 是 `window.APP_ICONS=[...]`，不是纯 JSON。
> 直接 `json.load(open(...))` 会报 `JSONDecodeError`。
> 也要注意 `"n"` 里有中文、`"f"` 里有 `%20`。

### 8.4 第二步：归一化 + 改名 + 输出到 `res/drawable-nodpi`

```python
# tools/import_app_icons.py
import json, pathlib, urllib.parse
from PIL import Image

HUB   = pathlib.Path("/path/to/ui-icons-hub/app-icons")
OUT   = pathlib.Path("app/src/main/res/drawable-nodpi")
SIZE  = 216                      # 统一到 216×216（占多数的档位）

# 上游名 -> 我们的 drawable 名（按需维护）
PICK = {
    "Camera":          "ic_app_camera",
    "Phone":           "ic_app_phone",
    "Ding Talk":       "ic_app_messages",
    "Poweramp":        "ic_app_music",
    # ...
}

data = json.loads((HUB / "icons.js").read_text(encoding="utf-8")[len("window.APP_ICONS="):].rstrip().rstrip(";"))
by_name = {e["n"]: urllib.parse.unquote(e["f"]) for e in data}

OUT.mkdir(parents=True, exist_ok=True)
missing = []
for upstream, target in PICK.items():
    rel = by_name.get(upstream)
    if rel is None:
        missing.append(upstream); continue
    im = Image.open(HUB / rel).convert("RGBA").resize((SIZE, SIZE), Image.LANCZOS)
    im.save(OUT / f"{target}.png", optimize=True)
print("exported", len(PICK) - len(missing))
if missing:
    print("MISSING:", ", ".join(missing))
```

要点：

1. **`convert("RGBA")`** —— 少数素材可能不是 RGBA，统一转一下，保住透明角；
2. **`resize((SIZE, SIZE), Image.LANCZOS)`** —— 缩放要选高质量重采样，否则圆角会出锯齿；
3. **`missing` 一定要打印**（同 §4.1 的教训）；
4. **`drawable-nodpi`** —— 因为我们已经把像素统一到 216 了，不想再让系统按密度缩放；
5. 如果最后 APK 太大，把输出换成 **WebP**（`im.save(..., "WEBP", quality=90)`），
   体积通常能降 60~70%，且 Android 原生支持。

### 8.5 第三步：改 `IosAppCatalog`，用 `drawable` 资源

**推荐做法：给 `IosApp` 加一个可空的图片资源字段，保留字形作为回退。**

```kotlin
data class IosApp(
    val id: String,
    val label: String,
    val glyph: ImageVector,
    val top: Color,
    val bottom: Color,
    val glyphTint: Color = Color.White,
    @DrawableRes val iconRes: Int? = null      // ← 新增：有真图标就用真图标
)
```

```kotlin
IosApp("camera", "相机", IosGlyphs.Camera, Color(0xFF9A9AA0), Color(0xFF45454A),
       iconRes = R.drawable.ic_app_camera)
```

渲染处（`IosHomeIcon` / `IosDockIcon` / 通知卡小图标 / 多任务卡片）统一走一个封装：

```kotlin
@Composable
fun IosAppIcon(app: IosApp, size: Dp, modifier: Modifier = Modifier) {
    val res = app.iconRes
    if (res != null) {
        Image(
            painter = painterResource(res),
            contentDescription = app.label,
            modifier = modifier.size(size)
            // ⚠️ 不要 clip：PNG 自带圆角（见 §2.3）
        )
    } else {
        // 回退：老的渐变 squircle + 字形
        Box(
            modifier.size(size)
                .clip(RoundedRectangle(size * 0.24f))
                .background(Brush.linearGradient(listOf(app.top, app.bottom))),
            contentAlignment = Alignment.Center
        ) {
            GlassIcon(app.glyph, app.glyphTint, size = size * 0.5f)
        }
    }
}
```

**为什么要"可空 + 回退"而不是直接替换**：
797 个名字里不一定找得到每一个 iOS 原生 App 的对应图标，
回退路径让"缺哪个补哪个"变成增量工作，而不是"必须一次凑齐 40 个才能编译"。

### 8.6 阴影怎么处理（**最容易出错的一步**）

旧实现的阴影形状是 `RoundedRectangle(15.dp)`。换成 PNG 后：

```kotlin
.shadow(
    elevation = 10.dp,
    shape = RoundedRectangle(62.dp * 0.27f),   // ≈ 16.7dp，与素材内建圆角对齐
    clip = false,                               // 只投影，不裁剪
    ambientColor = Color.Black.copy(alpha = 0.4f),
    spotColor = Color.Black.copy(alpha = 0.4f)
)
```

- `clip = false` 是必须的：`clip = true` 会**按这个 shape 真剪一刀**，
  和 PNG 自带的圆角错开就会出现"描边感"；
- 半径按 `0.27 × 边长` 估（实测数据，§2.3），**换尺寸时要跟着换算**，不要写死。

### 8.7 方案 B：不打包，放 `assets/` 运行时解码

如果将来想支持"797 张随便换"，可以走这条：

```kotlin
// assets/app-icons/<name>.png → Bitmap
val bitmap = remember(name) {
    context.assets.open("app-icons/$name.png").use { BitmapFactory.decodeStream(it) }.asImageBitmap()
}
Image(bitmap = bitmap, contentDescription = null, modifier = Modifier.size(62.dp))
```

取舍：

| | 方案 A（res/drawable-nodpi） | 方案 B（assets 运行时） |
|---|---|---|
| 编译期校验 | ✅ 资源不存在直接编译失败 | ❌ 运行时才炸 |
| 内存 | 系统管理 | 需要自己做 LRU 缓存 |
| 体积 | 只打用到的 | 全量进包 |
| 适合 | **主屏固定 40 个**（推荐） | 动态/可换图标包 |

### 8.8 验收清单

- [ ] 图标尺寸视觉一致（已归一化）
- [ ] **没有**二次圆角（没有多余的 `clip`）
- [ ] 阴影半径与图标内建圆角对齐，边缘没有"重影圈"
- [ ] 浅色壁纸 / 深色壁纸上都看得清
- [ ] APK 体积增量可接受（否则转 WebP 或缩小 `SIZE`）
- [ ] **授权已确认**（§2.4）—— 这一条没打勾，前面全部白做

## 10. 小结

```
①  ui-icons-hub 有两条管线，别混：
      A  data/*.js    → 215 个开源 SVG 集 → 编译期转 ImageVector（当前外壳用的）
      B  app-icons/   → 797 张苹果风格 PNG（预切圆角，尺寸不统一）→ 直接贴图（应该用的）

②  A 管线的四个必知：window.__ADD2 不是 JSON / 从第一个逗号后开始切 /
      数组末尾用 rindex("]") / 递归遍历才能取到 <g> 里的 path。

③  B 管线的四个必知：797 张 27MB / 214·216·400·595 四种尺寸 /
      四角透明、自带 27% 圆角（不要再切）/ 许可未明示。

④  颜色永远写白色、用 ColorFilter.tint 上色 —— 一套字形服务所有主题。

⑤  生成脚本一定要打印 MISSING 并检查 —— 静默少图标是最难发现的 bug。
```
