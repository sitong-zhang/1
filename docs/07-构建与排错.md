## 1. 唯一的硬性门槛：`minSdk ≥ 31`

**这是整套方案能不能用的分水岭，务必先确认。**

液态玻璃的底层是 **AGSL（Android Graphics Shading Language）**，通过 `android.graphics.RuntimeShader`
在运行时编译着色器。`RuntimeShader` 是 **API 31（Android 12）** 才引入的。

```
minSdk = 31   ✅ 有 RuntimeShader，玻璃可跑
minSdk = 30   ❌ 没有 RuntimeShader，玻璃组件一绘制就崩
```

崩的表现（真机上）：

```
java.lang.NoClassDefFoundError: Failed resolution of: Landroid/graphics/RuntimeShader;
```

或者 R8 之后变成 `NoSuchMethodError` / `VerifyError`。

> **如果你必须支持 API 30 及以下**，只有一条路：把 `drawBackdrop` 全部换成
> `Modifier.blur()` + 半透明 `background()` 的降级实现，并做版本分支。
> **那不是液态玻璃，是磨砂塑料。** 本章不覆盖这条路线。

另外两个运行时前提：

1. **必须开启硬件加速。** `AndroidManifest.xml` 里已显式声明
   `android:hardwareAccelerated="true"`；着色器走 GPU，软件渲染会直接失败或极慢。
2. **不要依赖 `Modifier.graphicsLayer` 之外的自绘降级路径**：AGSL 只会被 GPU 管线执行。

## 3. 三步把 APK 编出来

### 3.1 第一步：告诉 Gradle Android SDK 在哪

`local.properties`（在 `LiquidGlassShowcase/` 根下）**不进版本库**，必须自己建：

```properties
# 指向你本机的 Android SDK 根目录
sdk.dir=/path/to/android-sdk
```

也可以用环境变量替代：`ANDROID_HOME=/path/to/android-sdk`（两者取其一即可，
`local.properties` 优先级更高）。

SDK 里必须真的装了两个东西：

```
platforms/android-37.0          ← compileSdk = 37 需要它
build-tools/37.0.0              ← buildToolsVersion 需要它
```

缺了就用 `sdkmanager` 装：

```bash
sdkmanager "platforms;android-37" "build-tools;37.0.0"
```

### 3.2 第二步：用 JDK 17 跑 wrapper

```bash
cd LiquidGlassShowcase

# ⚠️ 关键：必须显式指定 JDK 17。系统默认的 java 大概率是 11，会直接失败。
export JAVA_HOME=/path/to/jdk-17

# 产物：app/build/outputs/apk/release/app-release.apk
./gradlew assembleRelease
```

只想快速验证代码能不能过：

```bash
./gradlew assembleDebug          # 未混淆、未压缩、签 debug 名，最快
./gradlew compileReleaseKotlin   # 只编译 Kotlin，不打包，更快
```

**首次构建会下载 Gradle 9.7.1 发行包 + 全部依赖**，需要有网。之后全部走
`~/.gradle` 缓存，实测第二次起构建时间从分钟级降到秒级。

在持久化的 CI/沙箱环境里，把 `JAVA_HOME` 固化进 wrapper 也更省事：

```properties
# LiquidGlassShowcase/gradle.properties（可选，方便交接）
org.gradle.java.home=/path/to/jdk-17
```

### 3.3 第三步：确认产物

```bash
ls -lh app/build/outputs/apk/release/
# app-release.apk        ← 已用 keystore/liquidglass-demo.jks 签名，可直接安装
# output-metadata.json
```

**成功标志**（实测输出结尾长这样）：

```
BUILD SUCCESSFUL in 4m 1s
43 actionable tasks: 1 executed, 42 up-to-date
```

> 看到 `42 up-to-date` 说明是增量构建，只重编了改动的那一个任务——
> 这正常，也正说明 `org.gradle.caching=true` 生效了。

## 4. 装到设备上

```bash
adb install -r app/build/outputs/apk/release/app-release.apk

# 查看已安装的包（applicationId = com.liquidglass.showcase）
adb shell pm list packages | grep liquidglass
```

**这台设备必须满足：Android 12（API 31）及以上 + 支持硬件加速的 GPU。**
模拟器同样可以，但要选 API 31+ 的镜像，并且**开启硬件加速（GPU 模式）**，
否则玻璃不会渲染。

启动后应该看到：**启动页（1.6 s 液态玻璃加载动画）→ 淡出缩放 1.2 s → 苹果系统外壳**。
如果启动页之后是黑屏或崩溃，按 §6.2 的顺序排查。

## 5. 构建配置逐项解释（改配置前先读）

`app/build.gradle.kts` 里每一块都有存在的理由：

| 配置 | 值 | 为什么 |
|---|---|---|
| `minSdk` | 31 | AGSL 下限，见 §1 |
| `targetSdk` | 34 | 与 37 的 compileSdk 解耦，避免过新的行为变更 |
| `isMinifyEnabled` | true | R8 全量混淆，把 1.25 MB 压到可接受 |
| `isShrinkResources` | true | 配合 R8 去掉未引用资源 |
| `signingConfigs.release` | 内置 demo keystore | 让 `assembleRelease` 直接产出**可安装**的包，省去自签名 |
| `packaging.dex.useLegacyPackaging` | true | 兼容旧安装器 |
| `dependenciesInfo.includeInApk` | false | 去掉依赖元数据，包更小 |
| `lint.checkReleaseBuilds` | false | 发布构建不跑 lint，避免无关警告中断 CI |
| `vcsInfo.include` | false | 不往 APK 里写 VCS 信息 |

> ⚠️ **demo keystore 是公开的**（口令 `liquidglass`，见 §7 许可）。
> 它只用于"让这个示例能直接装"，**不要用它签名你自己的正式应用**。

## 6. 报错速查

### 6.1 环境类（构建起不来）

| 现象 | 根因 | 修法 |
|---|---|---|
| `Android Gradle plugin requires Java 17 to run. You are currently using Java 11.` | 默认 `java` 是 11 | `export JAVA_HOME=/path/to/jdk-17`，或写进 `gradle.properties` 的 `org.gradle.java.home` |
| `Unsupported class file major version 6x` | 同上，JDK 版本不匹配 | 同上 |
| `SDK location not found. Define a valid SDK location with an ANDROID_HOME environment variable or by setting the sdk.dir path in your project's local.properties file.` | 没有 `local.properties` 也没有 `ANDROID_HOME` | 见 §3.1 |
| `Failed to find Build Tools revision 37.0.0` | SDK 里没装这个版本的 build-tools | `sdkmanager "build-tools;37.0.0"` |
| `Failed to find platform 'android-37'` / `compileSdk 37 not found` | SDK 里没装 platform 37 | `sdkmanager "platforms;android-37"` |
| `Could not resolve io.github.kyant0:backdrop:2.0.0` | 没网 / 代理没配 | 检查 `HTTP_PROXY` / `HTTPS_PROXY`；确认 `mavenCentral()` 可达（§2 的 `settings.gradle.kts` 已经配好仓库） |
| `Could not find io.github.kyant0:shapes` | 只加了 backdrop，没加 shapes | `libs.versions.toml` + `app/build.gradle.kts` 两处都要有（§2） |
| `./gradlew: Permission denied` | wrapper 脚本没有执行位 | `chmod +x gradlew` |
| wrapper 起不来 / `Could not find or load main class org.gradle.wrapper.GradleWrapperMain` | `gradle/wrapper/gradle-wrapper.jar` 没提交进来 | 确认该文件存在于仓库中 |

### 6.2 运行时类（装机后崩 / 黑屏）

| 现象 | 根因 | 修法 |
|---|---|---|
| `NoClassDefFoundError: android.graphics.RuntimeShader` | `minSdk < 31` 或跑在 API < 31 的设备上 | 换 API 31+ 设备；确认 `minSdk = 31` |
| 玻璃是全黑 / 全透明方块 | backdrop 没录到内容 | **最常见**：检查 `Modifier.layerBackdrop(...)` 是否挂在了真正画壁纸的那个节点上（`README` §1 铁律 1、`docs/02` §2） |
| 玻璃里是"上一帧"的画面 | 记录节点画得比采样节点晚 | 内容层必须**先于**浮层绘制（`docs/02` §2.4、§6） |
| 一动就掉帧 | 无条件挂了 `layerBackdrop` | 改成条件录制（`docs/02` §7、`docs/05` §3.2） |
| 界面全灰、没有颜色 | 少了 `vibrancy()` | `effects` 第一行加 `vibrancy()`（`docs/01` §2） |
| 边缘红蓝彩边 | 静止态开了色散 | `chromaticAberration = false`，只在按下/拖动时打开（`README` 铁律 4） |
| 圆角看着"不对"，像普通圆角 | 用了 `androidx.compose.foundation.shape.RoundedCornerShape` | 改用 `com.kyant.shapes.RoundedRectangle`（G2 连续曲率，`docs/03` §3） |
| 真机发热明显 | 记录层是每帧一次全屏离屏渲染 | 见 §8 |

### 6.3 编译期类（Kotlin / Compose）

| 现象 | 根因 | 修法 |
|---|---|---|
| `Unresolved reference: lens` / `vibrancy` | `effects` 里没有对应的 import，或 backdrop 版本不对 | 确认依赖是 `2.0.0`；`lens` / `blur` / `vibrancy` 都是 `BackdropEffectScope` 的成员 |
| `Unresolved reference: RoundedRectangle` | 用了 foundation 的包 | `import com.kyant.shapes.RoundedRectangle` |
| `@Composable invocations can only happen from ...` | 在非 Composable 作用域里调用了 `rememberLayerBackdrop()` 等 | `rememberLayerBackdrop` 必须在 `@Composable` 里调 |
| `Type mismatch: inferred type is Float but Dp was expected`（或反之） | 忘了 `.dp.toPx()` | `lens` / `blur` 的长度参数一律 `xx.dp.toPx()`（`README` 铁律 3） |
| Compose 编译器报版本不匹配 | Kotlin 与 Compose 编译器插件版本不一致 | 本工程用 AGP 9 内置 Kotlin 支持 + `org.jetbrains.kotlin.plugin.compose` 同版本（`2.4.10`），不要手动加 `composeOptions.kotlinCompilerExtensionVersion` |

### 6.4 最有效的三步定位法

出问题时，**按这个顺序排除，90% 的玻璃问题在第一、二步就暴露**：

```
第 1 步  把某一处 drawBackdrop 的 backdrop 换成"固定颜色的 EmptyBackdrop/纯色纹理"
         → 如果玻璃"亮了"，说明是 backdrop 录制的问题，不是材质参数的问题
第 2 步  临时把 onDrawSurface 的染色去掉
         → 如果折射出现了，说明是染色盖住了玻璃（README 铁律 6）
第 3 步  临时把 highlight / shadow 关掉
         → 用来确认"边缘不对"到底是高光参数问题，还是 shape 问题
```

**永远先确认"背景有没有被录进去"，再去调参数。** 参数调不出内容。

## 8. 性能验证怎么做（不是"感觉卡不卡"）

液态玻璃唯一的系统性开销是 **`layerBackdrop` 记录层：每帧一次全屏离屏渲染**。
验证方法：

1. **开发者选项 → GPU 呈现模式分析（Profile HW UI rendering）**
   看柱状图里的 `Draw` / `Sync`。玻璃静止、没有任何浮层打开时，柱高应该明显低于面板打开时。
2. **`adb shell dumpsys gfxinfo com.liquidglass.showcase framestats`**
   看 `janky frames` 比例。
3. **对比开关**：临时把所有条件录制的开关关掉（让 `layerBackdrop` 常挂），
   帧率应该明显下降——**这个差值就是"条件录制"帮你省下来的**。

优化清单（按收益排序，细节见 `docs/02` §9）：

- 条件录制：**只在浮层真的要读它时才挂 `layerBackdrop`**（收益最大）；
- 记录层范围尽量小，不要动辄全屏；
- 静态页面不要挂着不动；
- 减少同一帧内的 backdrop 数量。

## 9. 给 AI 的"从零复刻"操作清单

如果你（AI）拿到这个仓库，要从零把效果跑起来，**严格按这个顺序**：

```
① 读 README.md            → 建立心智模型（背景纹理 → 采样 → 折射），记住十条铁律
② 读 docs/01              → 理解 6 条视觉线索 ↔ 6 个 API 的对应关系
③ 读 docs/02              → 搞清 LayerBackdrop / Combined / 防反馈环
④ 读 docs/03              → 把 drawBackdrop 的全部参数过一遍
⑤ 抄 docs/04 的配方       → 不要自己发明参数
⑥ 照 docs/03 的最小示例搭一个页面，确认玻璃能显示
   └─ 显示不出来 → 回 §6.4 一步一步排除，先确认 backdrop 有没有录进内容
⑦ 需要完整 App 外壳 → 读 docs/05（z-order、backdrop 分配表、条件录制）
⑧ 需要图标       → 读 docs/06（两条管线的区别 + 苹果图标分区的切换方案）
⑨ 编译不过       → 本章
```

**四条不能违反的工程约束**（违反了不是"不好看"，是"跑不起来"）：

1. `minSdk ≥ 31`；
2. JDK 17 构建；
3. `effects` 顺序永远是 `颜色 → blur → lens`；
4. 所有长度参数 `.dp.toPx()`。

## 10. 小结

- **构建这件事本身很简单**：`local.properties` 写 `sdk.dir` → `JAVA_HOME` 指向 JDK 17 → `./gradlew assembleRelease`。
- **真正会卡住你的只有两类问题**：环境版本（§6.1）和 backdrop 录制（§6.2）。
  后者占了实际开发中 90% 的时间，解法永远是"**先确认背景录进去了没有**"。
- **本仓库故意不含 APK**：APK 是产物。你能编出 1.25 MB 的那个 `app-release.apk`，
  就说明这套液态玻璃的完整环境已经复刻成功了。

**至此，`README` + `docs/01~08` 已覆盖：光学原理 → 架构 → API → 配方 → 外壳实战 → 资产 → 构建排错。**
